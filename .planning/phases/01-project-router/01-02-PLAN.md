  <action>
Create `skills/project/SKILL.md` following the `create-prd/SKILL.md` pattern. Target 200-300 lines. The file has three parts: frontmatter, rules, and numbered steps.

**FRONTMATTER** — YAML frontmatter block (delimited by triple-dash lines) with these exact fields:
- `name: project`
- `description:` (use the multi-line scalar from RESEARCH.md — "Project orchestrator. Bootstraps progress.txt on first run, reports project state, and routes to the next skill on every subsequent invocation. Use when starting a new project, checking project status, or deciding what to do next. Phrases like 'where am I', 'project status', 'what's next' are good triggers.")
- `disable-model-invocation: true`

**TITLE AND INTRO:**
- H1 heading: `/project — Project Orchestrator`
- One-line description: "Bootstraps project state on first run, reports status, and routes to the correct next skill on every subsequent invocation. Read-only after bootstrap."

**RULES SECTION** — Key behavioral rules (keep concise, ~15 lines):
- Read all state files fresh from disk on every invocation — never rely on conversation memory (STATE-03)
- After bootstrap, `/project` is strictly read-only — it never modifies `progress.txt` or any other file (PROJ-10)
- Route by telling the user what to run — never auto-dispatch or invoke other skills (DD-2)
- When both `milestone-status.txt` and `progress.txt` need updates, downstream skills must write `milestone-status.txt` first (STATE-04 — document this contract here for downstream skill authors)
- Use `AskUserQuestion` for interactive prompts (2-4 options, max 12-char headers)

**STEP 1 — Detect Project State:**
- Read `progress.txt` from the project root
- If the file does not exist, proceed to Step 2 (Bootstrap)
- If the file exists, proceed to Step 3 (Read State)

**STEP 2 — Bootstrap:**
- This is the ONLY time `/project` writes to disk
- Read `references/progress-format.md` for the exact bootstrap template
- Detect greenfield vs brownfield: if project directory is empty or contains only boilerplate (README, .gitignore, package.json with no src/), it is greenfield (per DD-10)
- If greenfield: use the greenfield variant (Gate 0 as `[-] Skipped (greenfield)`)
- If brownfield: use the standard template (Gate 0 as `[ ]`)
- Ask the user for a project name using `AskUserQuestion` (or derive from directory name)
- Use the Write tool to create `progress.txt` with the template, replacing `<Project Name>` and `<ISO date>`
- Read the file back and confirm it was created correctly
- Show the user the created file content
- Proceed to Step 3 (Read State) to display the initial status report

**STEP 3 — Read State:**
- Read `progress.txt` from disk (fresh read — STATE-03)
- Parse all gate entries, milestone summary lines, and spike entries
- For each milestone found, read its `milestone-status.txt` (path from milestone summary line)
- Read `references/routing-logic.md` for validation rules
- Perform artifact validation (PROJ-04): for each `[x]` gate, check artifact path exists on disk
- Perform consistency validation (PROJ-05): compare milestone feature counts between progress.txt and milestone-status.txt
- Collect all warnings (missing artifacts, consistency divergences)
- Proceed to Step 4 (Status Report)

**STEP 4 — Status Report:**
- Read `references/status-report-format.md` for the exact output format
- If Gate WB is `[ ] Pending`: show the gentle reminder at the top per D-09 (do NOT suppress the rest of the report — this overrides the strict PROJ-07 reading)
- Display the structured summary: GATES (with dates/artifacts), ACTIVE MILESTONE (expanded), COMPLETED/UPCOMING milestones (one-line summaries), SPIKES (all, per D-02)
- Display inline warnings per D-06 — directly after the gate or milestone entry they affect
- If consistency divergence detected: display the warning and ask user to acknowledge before proceeding to routing (per D-07 blocking behavior)
- Proceed to Step 5 (Route)

**STEP 5 — Route:**
- Read `references/routing-logic.md` for the complete routing table
- Check for re-planning intent: if the user's message contains keywords like "goals changed", "revise PRD", "pivot", "re-plan", "revise milestone" (per D-05), route to the appropriate skill in revision mode (PROJ-08, PROJ-09)
- Determine the recommended next action based on current state using the routing table
- Display per D-03: one RECOMMENDED action highlighted, with 2-3 "Also available" alternatives listed below
- Per D-04: only show alternatives valid for the current project state
- If Gate WB needs to be offered (per DD-11, D-08): use `AskUserQuestion` with options "Yes" (12 chars max), "Skip", "Defer" and brief 2-3 sentence explanation of Working Backwards value

**ERROR HANDLING** — At the end of the file:
- If `progress.txt` is malformed (missing headers, corrupted entries): report the issue, suggest the user check git history for a clean version. Do not attempt to repair.
- If a `milestone-status.txt` is missing but referenced in `progress.txt`: warn but continue — the milestone may have been partially created.
- If the user's intent is ambiguous: ask for clarification using `AskUserQuestion` rather than guessing.

**LINE BUDGET:** SKILL.md must stay under 300 lines. All detailed specs (format templates, routing tables, output formats) live in the `references/` files and are loaded via `Read` at the appropriate steps. Do NOT inline the bootstrap template, routing table, or status report format — reference them.
