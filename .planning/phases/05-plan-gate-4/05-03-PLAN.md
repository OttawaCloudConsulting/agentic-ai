Create `docs/skills/plan.md` following the exact pattern from `docs/skills/milestone.md`. The detail doc structure is: Purpose, When to Use, When NOT to Use, Behavior (numbered subsections), Artifacts, Skill Files, Related Skills.

**Header:**
```markdown
# /plan

**Source:** `skills/project/plan/`
**Command:** `/plan`
**Activation:** Manual only (`disable-model-invocation: true`) -- invoked via slash command. Not auto-triggered by conversational phrases.
```

**Purpose section:**
Per-feature implementation planning skill that produces detailed feature plans with sub-feature breakdown, interface contracts, sizing validation, and test commands. Each invocation plans one feature from an approved milestone. Supports re-plan mode for already-planned features with diff-focused revision. Gate 4 approval updates the feature entry in `milestone-status.txt` from `[ ]` to `[~] planned, awaiting build`. After approval, offers to plan the next unplanned feature in the same session.

**When to Use section:**
- Planning a specific feature after milestone definition (Gate 3 in progress)
- Creating implementation plans with sub-feature breakdown
- Re-planning a feature after scope changes or implementation discovery
- Continuing feature planning across a milestone (auto-selects next unplanned)

**When NOT to Use section:**
- When you want to check project status or get routing (use `/project`)
- When you want to define project scope or create a PRD (use `/define` -- runs Gates 0/WB/1)
- When you want to design system architecture (use `/design` -- Gate 2)
- When you want to define milestones and features (use `/milestone` -- Gate 3)
- When you want to implement code (use `/build`)

**Behavior section** (numbered subsections matching SKILL.md steps):

1. **Mode Detection** -- Reads progress.txt and milestone-status.txt. Auto-detects active milestone (first at [ ] or [~]). Auto-selects next unplanned feature. Detects re-plan mode when plan file already exists. Reports when all features are planned.

2. **Input Loading and Codebase Scan** -- Reads milestone README, prd.md, architecture doc, progress.txt, milestone-status.txt. Spawns a sub-agent for feature-targeted codebase scan (5-15 files relevant to the feature, not architecture-wide). Reads spike artifacts only when user explicitly references them.

3. **Plan Generation and Review** -- Generates feature plan with 12 sections: Summary, Acceptance Criteria, Approach, Sub-Features, Interface Contracts, Edge Cases, Test Command, Test Strategy, Documentation, Files to Create/Modify, Dependencies, Architectural Deviations. Validates sub-feature sizing against ~120k-token guideline. Presents 1-2 tradeoff callouts. Whole-plan Approve/Revise cycle (not section-by-section). Generates gate-4 review checklist with 5 static items plus auto-generated items.

4. **Re-plan Mode** -- Auto-detected when plan file exists. Diff-focused revision: asks "What changed?", revises only affected sections using Edit tool. Generates fresh review checklist. Same Approve/Revise approval flow.

5. **Completion** -- Updates milestone-status.txt with plan path and `[~] planned, awaiting build` status. Does NOT write to progress.txt. Offers to plan next unplanned feature.

**Artifacts section:**

| Artifact | Path | Created By |
|----------|------|------------|
| Feature plan | `milestones/<NN>-<name>/plans/<feature-slug>.md` | /plan |
| Gate 4 review | `milestones/<NN>-<name>/reviews/gate-4-<feature-slug>-review.md` | /plan |
| milestone-status.txt | `milestones/<NN>-<name>/milestone-status.txt` | /plan (updates only) |

```
│   └── progress-format.md            ← State file format spec (own copy)
└── assets/
    └── feature-plan-template.md       ← Feature plan section template
```
