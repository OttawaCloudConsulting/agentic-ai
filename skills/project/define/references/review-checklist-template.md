# Gate Review Checklist Template

This is the shared review format for all `/define` gate reviews (Gate 0, Gate WB, Gate 1). Each gate generates a review checklist file using this template structure, with gate-specific static items below and content-specific items auto-generated by Claude based on actual artifact content.

## File Header

Every review checklist file begins with this header:

```
# Gate {N} Review -- {Gate Name}

**Artifact:** {path to primary artifact}
**Status:** [ ] Pending
**Reviewer(s):**
**Date:**
```

## Checklist Structure

Each review checklist has two tiers of items:

1. **Static items** (from this template, per gate): Baseline checklist items that always appear for a given gate. These are defined in the gate-specific sections below.

2. **Content-specific items** (auto-generated by Claude): Items added based on actual artifact content. These appear after the static items and are prefixed with `[Auto]`. Examples: specific assumptions to verify, specific patterns to confirm, specific risks to evaluate.

Format:

```
## Checklist

- [ ] Static item from template
- [ ] Static item from template
- [ ] [Auto] Content-specific item based on artifact
- [ ] [Auto] Content-specific item based on artifact
```

## Gate 0: Codebase Assessment -- Static Items

These items always appear in `docs/reviews/gate-0-review.md`:

- `[ ] Are the detected patterns accurate for the current codebase?`
- `[ ] Are there patterns listed as "carry forward" that should be changed?`
- `[ ] Are there existing patterns not detected that the model should follow?`
- `[ ] Are the open questions answerable? Provide answers.`
- `[ ] Are the assumptions stated in the assessment correct?`

## Gate WB: Working Backwards -- Static Items

These items always appear in `docs/reviews/gate-wb-review.md`:

- `[ ] Does the press release describe a clear customer outcome?`
- `[ ] Is the problem statement accurate and specific?`
- `[ ] Does the solution description match the intended scope?`
- `[ ] Are the FAQ answers consistent with the press release?`
- `[ ] Are internal feasibility concerns addressed in the Internal FAQ?`

## Gate 1: Scope Review -- Static Items

These items always appear in `docs/reviews/gate-1-review.md`:

- `[ ] Are the goals specific and measurable?`
- `[ ] Are the non-goals clearly justified?`
- `[ ] Are external dependencies identified with owners and status?`
- `[ ] Is the risk assessment comprehensive?`
- `[ ] Are configuration parameters fully specified (type, description)?`
- `[ ] Are outputs clearly defined?`

## Completion Rules

All checklist items must be resolved before gate approval can be recorded:

- **`[x]`** -- Verified: Item has been reviewed and confirmed correct.
- **`[-]`** -- N/A with reason: Item does not apply to this project/artifact. A brief reason must follow (e.g., `[-] No external dependencies -- single-repo project`).

No item may be left as `[ ]` at approval time. Every item must reach `[x]` (verified) or `[-]` (N/A with reason).

**Pre-check process:**
1. Claude pre-checks items it can verify programmatically (e.g., file exists, required sections present, format correct).
2. Claude presents remaining unchecked items to the user for review and resolution.
3. User marks each remaining item as `[x]` or `[-]` with reason.
4. Gate approval is recorded only after all items are resolved.

## Reviewer Comments

Each review checklist ends with a comments section:

```
## Reviewer Comments

(none)
```
