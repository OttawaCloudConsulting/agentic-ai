# Debate Mode — Detailed Rules

Debate mode enables structured adversarial dialogue between red-team agents and green-team
defenders via Claude Code Agent Teams. This file documents the green-team persona, debate
protocol, and finding status labels referenced in SKILL.md Step 3h.

## Activation

Debate mode is triggered by the `--debate` flag in the user's invocation:

```
/red-team <target> --debate              # 1 round of debate
/red-team <target> --debate --rounds 3   # 3 rounds of debate
```

Default rounds: 1. Maximum rounds: 5 (higher values capped with a note to the user).

## Green-Team Persona

Green-team agents are dynamically generated by the orchestrator (no persona file in
`references/`). Each green-team agent receives:

```
ROLE:
You are a green-team defender in a red-team review. Your job is to challenge
red-team findings by providing evidence-based rebuttals.

POSTURE:
- Assume the artifact is well-designed until shown specific evidence of flaws.
- Challenge vague, speculative, or over-generalized red-team findings.
- Provide counter-evidence: code references, documentation, industry practices.
- Acknowledge valid findings honestly — do not reflexively defend everything.
- "I disagree" without evidence is NOT a valid rebuttal.

RULES:
1. Every rebuttal must cite specific evidence: code, documentation, design rationale.
2. For each red-team finding, respond with one of:
   - ACCEPT: The finding is valid. State why briefly.
   - REBUT: The finding is invalid or overstated. Provide counter-evidence.
   - CONTEST: The finding has merit but the severity or framing is wrong.
     Provide alternative assessment with evidence.
3. Do not introduce new findings or concerns. Your scope is the red-team's findings.
4. Be concise. One paragraph per rebuttal, focused on evidence.

---

RED-TEAM FINDINGS TO REVIEW:
{contents of {lens}-findings.md}

---

ARTIFACT (for reference):
{artifact content or summary}
```

## Debate Protocol

### Agent Teams Coordination

1. **Red-team agents** run first (Step 3f) and write initial findings.
2. **Green-team agents** are spawned after Step 3g verification, one per red-team lens.
3. Each green-team agent is paired with its corresponding red-team lens findings.
4. Communication happens via Claude Code Agent Teams messaging:
   - Green-team sends rebuttals to the corresponding red-team agent.
   - Red-team agent evaluates rebuttals and updates findings.
5. For `--rounds > 1`, steps 3-4 repeat: green-team responds to updated findings,
   red-team re-evaluates.

### Pairing Rules

| Red-Team Lens | Green-Team Defender |
|---------------|-------------------|
| Each selected lens | One dedicated green-team agent |

Green-team agents are spawned in parallel (single message with multiple Agent calls),
same as red-team agents.

### Round Flow

```
Round 1:
  Green-team reads initial findings → sends rebuttals
  Red-team evaluates rebuttals → updates Status on each finding

Round 2+ (if --rounds > 1):
  Green-team reads updated findings → sends follow-up rebuttals
  Red-team evaluates → updates Status again (can change from prior round)

Final:
  Red-team rewrites findings file with Defense and Status fields
```

## Finding Status Labels

After debate, each finding carries a Status label:

| Status | Meaning | Report Treatment |
|--------|---------|-----------------|
| **Sustained** | Red-team evidence holds despite green-team challenge | Included in report at original severity |
| **Rebutted** | Green-team provided compelling counter-evidence | Moved to Methodology section under "Rebutted findings" |
| **Contested** | Both sides presented valid evidence; no clear winner | Included in report with both evidence and defense summary |

### Status Assignment Rules

- **Sustained:** The green-team's rebuttal lacks specific counter-evidence, or the
  red-team can demonstrate the rebuttal does not address the core issue.
- **Rebutted:** The green-team cites specific code, documentation, or design rationale
  that directly invalidates the finding's premise or evidence.
- **Contested:** Both sides have specific, valid evidence. The red-team acknowledges
  the defense has merit but maintains the finding based on their evidence.

A finding that receives no rebuttal (green-team accepted it) is marked **Sustained**.

## Updated Findings Format

When debate mode is active, each finding in the `{lens}-findings.md` file gains two
additional fields after `Recommendation`:

```markdown
### Finding N: {title}
- **Severity:** {level}
- **Category:** {category}
- **Observation:** {what was found}
- **Evidence:** {evidence}
- **Impact:** {impact}
- **Recommendation:** {recommendation}
- **Defense:** {green-team rebuttal summary — "No rebuttal received" if green-team accepted}
- **Status:** Sustained | Rebutted | Contested
```

## Error Handling

| Scenario | Action |
|----------|--------|
| Green-team agent fails to produce rebuttals | Mark all paired findings as Sustained (no defense) |
| Red-team agent fails to respond to rebuttals | Keep initial findings unchanged, mark as Sustained |
| Agent Teams communication fails | Fall back to non-debate mode, note in methodology |
| All green-team agents fail | Proceed to synthesis without debate, note in methodology |
